Тема: Разработка приложения для учёта и обработки заявок службы поддержки
В современном мире почти каждая организация сталкивается с необходимостью быстро принимать, обрабатывать и контролировать обращения пользователей. Это могут быть заявки на ремонт оборудования, проблемы с доступом, ошибки в программах или обычные вопросы сотрудников. Если такие обращения хранить в переписке или таблицах, легко потерять важную информацию: кто создал заявку, кто за неё отвечает, на каком она этапе и не просрочено ли её выполнение. Поэтому для таких задач используют help desk системы.
В рамках проекта было разработано десктопное приложение для учёта заявок службы поддержки. Его основная цель — упростить работу с обращениями пользователей и сделать процесс обработки более понятным. Приложение позволяет регистрировать пользователей, создавать тикеты, назначать ответственных сотрудников, менять статусы заявок, оставлять комментарии и контролировать сроки выполнения.
Проект написан на языке C# с использованием платформы .NET 9 и библиотеки Avalonia UI. Avalonia выбрана потому, что она позволяет создавать настольные приложения с современным интерфейсом. В отличие от обычного консольного приложения, здесь пользователь работает через окна, кнопки, списки и формы. Это делает систему более удобной для реального использования.
Для хранения данных используется PostgreSQL. В базе данных сохраняются пользователи, заявки, комментарии, SLA-политики и другая информация. Подключение к базе вынесено в файл appsettings.json, поэтому при необходимости можно изменить адрес сервера, имя базы или пароль без изменения кода программы. Для работы с базой используется Entity Framework Core. Он позволяет описывать таблицы через C#-классы и работать с данными не через ручные SQL-запросы, а через репозитории и сервисы.
В проекте используется разделение на несколько логических слоёв. В слое Domain находятся основные модели: пользователь, тикет, комментарий, SLA-политика. В слое Application расположены сервисы и DTO-классы, которые отвечают за бизнес-логику. Например, сервис авторизации проверяет логин и пароль, а сервис тикетов создаёт заявки и меняет их статус. В слое Infrastructure находится работа с базой данных, репозитории и настройка зависимостей. Такой подход делает код более понятным: каждая часть отвечает за свою задачу.
В системе предусмотрены роли пользователей. Обычный пользователь может создавать заявки и просматривать свои обращения. Агент поддержки может брать заявки в работу и менять их состояние. Администратор имеет больше возможностей, например управляет пользователями и настройками. Такая модель ролей нужна, чтобы разные участники системы не имели лишнего доступа.
Важной частью проекта является SLA. SLA — это правила, которые определяют, за какое время нужно отреагировать на заявку и решить её. Например, заявка с низким приоритетом может выполняться дольше, а срочная должна быть обработана быстрее. В приложении есть настройки SLA для разных приоритетов: низкий, средний, высокий и срочный. Это помогает контролировать качество работы службы поддержки.
Для запуска базы данных используется Docker Compose. Это удобно, потому что не нужно вручную устанавливать PostgreSQL и настраивать его с нуля. Достаточно запустить команду docker-compose up -d, после чего база данных и pgAdmin поднимаются автоматически. Затем через миграции Entity Framework можно создать нужные таблицы в базе. В Visual Studio это делается через команду Update-Database.
Можно сказать, что проект получился не просто учебным примером, а заготовкой реальной help desk системы. В нём уже есть авторизация, роли, работа с базой данных, тикеты, комментарии и настройка сроков выполнения. Конечно, приложение ещё можно развивать: улучшить интерфейс, добавить вложения файлов, уведомления, фильтры, отчёты и отдельные проекты для слоёв архитектуры. Но даже в текущем виде оно показывает, как устроена типичная информационная система для обработки заявок.
В заключение можно отметить, что разработка такого приложения помогает понять сразу несколько важных тем: работу с базой данных, построение пользовательского интерфейса, разделение кода на слои, авторизацию, роли пользователей и миграции. Этот проект полезен не только как программа, но и как пример практического применения C# и .NET в задаче, близкой к реальным рабочим системам.
